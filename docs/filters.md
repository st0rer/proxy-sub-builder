# Фильтры: ложные срабатывания и потерянные ноды

Каждый фильтр, который выкидывает ноды, проверялся против «истины» — той же
проверки, но с двумя попытками и длинными таймаутами. Ниже замеры и выводы.

## Ступени проверки

```
фаза 0   TCP-коннект 3 с          (только для TCP-протоколов; дешёвый предфильтр)
ступень 1 https://www.gstatic.com/generate_204          7 с   → 204
ступень 2 http://cp.cloudflare.com/generate_204        10 с   → 204
ступень 3 https://speed.cloudflare.com/__down?bytes=16384  12 с → 200 + 16 КБ тела
второй проход по «мёртвым»:
         cp-cf 15 с → тело 18 с → gstatic 12 с
```

Три ступени нужны потому, что одиночный URL даёт ложные отсевы: у части выходов
gstatic недоступен, а данные при этом ходят. Замер на 42 отвергнутых нодах: 4
живых (27 % от достижимых) при проверке одним URL.

## Что было сломано (замер 16.11.2026, 101 нода, мобильный оператор)

| метрика | значение |
|---|---|
| быстрый режим: живых | 10 |
| «истина» (2 попытки, 12/15/20 с) | 14 |
| **ложных отрицаний** | **4 (28 % рабочих)** |
| ложных положительных | 0 |
| TCP на 3 с / на 8 с | 43 / 41, «только на 8 с» — **0** |

Потери — 3 Shadowsocks и 1 VLESS, все на flap'ах и таймаутах 7/10 с.

## Решения

- **Второй проход по мёртвым** с длинными таймаутами. В боевом прогоне вернул
  8 нод из 13 — выход удвоился. Стоимость: ~40 с на мёртвую ноду, трафика нет.
- **Проверка размера тела.** Принимать `200` без проверки нельзя: заглушка
  (страница воркера, каптивный портал оператора) отвечает `200` и не везёт
  данные. На запросе `bytes=16384` тело меньше 15 КБ = не CDN.
- **`speed_measured`.** Ноль бывает двух сортов: «не мерили» и «мерили, не
  поехало». Второй выбрасывается, первый сохраняется. Без этого флага три
  нулевых ноды попали в подписку.
- **Порог скорости 0.03 МБ/с**, а не 0.08: ноды на 0.04–0.06 МБ/с отдают
  трафик (320–480 кбит/с — хватает для мессенджеров и веба). Клиент сам
  поставит их в конец списка.
- **`exit_ip` не отсеивает.** Прохождение 16 КБ с CDN уже доказывает выход;
  `api.ipify.org` у части выходов блокируется — это было ещё одно ложное
  отрицание. Флаг `REQUIRE_EXIT_IP=1` возвращает строгий режим.
- **Карантин протестированных 48 ч**, не неделя: нода, отвалившаяся на час,
  к вечеру оживает.
- **TCP-таймаут 3 с менять не нужно** — проверено, ни одной ноды не теряет.
- **Дедуп не теряет быстрые копии**: сортировка по скорости идёт до дедупа,
  поэтому из двух копий одного подключения остаётся быстрая.

## Правило

> Любой фильтр, который выкидывает ноды, надо мерить против «истины» с повтором
> и длинными таймаутами. Иначе тихо теряется четверть рабочих — и это выглядит
> как «ноды кончились», а не как баг.

## Как повторить замер

```bash
# 1. кандидаты тем же отбором, что и в бою
python3 - <<'PY'
import importlib.util as u, json, sys
sys.path.insert(0, "scripts")
spec = u.spec_from_file_location("mp", "scripts/mobile_push.py")
mp = u.module_from_spec(spec); spec.loader.exec_module(mp)
json.dump(mp.pick_candidates(), open("/tmp/cand.json", "w"))
PY
# 2. прогнать каждый кандидат дважды: быстрым режимом и «истиной»
#    (см. scripts/pi_sb_verify.py — там обе лестницы URL)
```
