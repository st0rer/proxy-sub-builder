# Телеграм как источник (без аккаунта)

Публичные превью `https://t.me/s/<канал>` отдают последние посты в HTML без
авторизации. Этого достаточно, чтобы вынимать конфиги, но недостаточно, чтобы
ходить вглубь.

## Что проверено и как работает

- **Ширина важнее глубины.** 30 страниц одного канала дали 5 990 ссылок и
  **0 живых** из 15 проверенных; 400 разных каналов дают поток, где живые
  встречаются регулярно. Вывод: наращивать список каналов, а не историю постов.
- **`?q=` несовместим с `?before=`.** Поиск внутри канала даёт 76 ссылок против
  200 при обычной пагинации, и глубина с ним не работает.
- **Агрегаторы живут хуже тематических каналов.** Крупные сборники
  (`MhdiTaheri`, `Au1rxx`) — 0 живых из 39 и 0 из 25: там лежит то, что умерло
  месяц назад.
- **Новые каналы дают 0–9 %.** Из 55 найденных новичков — 0 живых. Смысл в них
  не в мгновенной отдаче, а в накоплении: часть оживёт позже.

## Скрипты

`discover_channels.py` — где брать новые каналы:

- списки из 12 проверенных активных репозиториев (`Argh73/V2Ray-Vault`,
  `therealaleph/Shin-TG-V2ray-Collector`, `mohamadfg-dev/telegram-v2ray-configs-collector`,
  `tahmaseb73/configs-collector-v2ray`, `qweered/tg-proxy-parser`, `Surfboardv2ray/TGParse`,
  `CattMurr/FREE-VPN-VIA-PLANET`, `3yed82/TVC`, `vpnineh/TGC`, `chenweimin30-hue/-VPN` и др.) —
  более 1 400 уникальных каналов;
- `--search` через SearXNG (`site:t.me`) и GitHub Code Search через `gh api`;
- отклонённые каналы хранятся в `tg_rejected.json` с TTL 3 дня, чтобы не
  перепроверять пустые каждый цикл.

`tg_scrape.py 400` — сбор:

- пагинация `?before=`, состояние в `tg_state.json`, 16 потоков, backoff 3–9 с;
- понимает base64-блобы (в них бывает список ссылок целиком);
- **Sub-in-Sub Harvester**: извлекает и скачивает внешние подписки из текста постов
  (ссылки на raw GitHub, воркеры Cloudflare `workers.dev`, `/sub`, эндпоинты с `token=`),
  кэшируя запросы в `tg_fetched_subs.json` с TTL 12 часов;
- вынимает упоминания `t.me/...` и `@name` — из них появляются новые каналы;
- умный скоринг каналов при выборке: каналы с подтвержденным выходом живых нод
  (`verified_alive`) опрашиваются первыми, затухающие каналы уходят в конец;
- статистика в `tg_stats.json` (`links`, `last_links`, `zero_runs`, `verified_alive`);
- канал с `zero_runs >= 6` уходит в отклонённые.

`fast_pass.py` — быстрый проход каждые 3 часа по топ-15 каналам: первая страница
с курсором, проверка `sb_verify` (таймаут 6 с, 16 потоков), публикация. Свежий
конфиг проверяется через минуты, а не через часы. Каналы, чьи ноды подтвердили
живость, получают повышенный рейтинг `verified_alive`.

## Чего стоит каталог

`tgstat.ru` отдаёт 403, `telemetr.me` и `tlgrm.ru` рендерят JS без username.
Полноценный каталог без аккаунта недоступен — отсюда ставка на списки из
репозиториев и на накопление.

## Про MTProto

Сессия telethon дала бы комментарии, похожие каналы и поиск, но: сессии живут
недолго, а QR-авторизация в прошлый раз отвалилась за сутки. Поэтому проект
работает на публичных превью. Если добавляете MTProto — держите сессию в
`$PROXY_SUB_HOME/secrets/` и не публикуйте её никуда.

## Дисциплина опроса

Опрос каждые 30 минут — лишняя нагрузка: конфиги не появляются так часто.
Рабочая схема: полный проход в общем цикле (6 часов) + `fast_pass` каждые
3 часа по самым продуктивным каналам.
