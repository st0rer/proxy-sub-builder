# Архитектура

Конвейер собран вокруг одного принципа: **решение о ноде принимает движок,
которым пользуется клиент**, а не эвристика по открытому TCP-порту.

```
источники            сбор                проверка                  публикация
─────────           ─────               ──────────                ───────────
GitHub-списки  ┐
каталоги       ├─→ all_links.json ─→ alive.json ─→ verified.json ─→ nodes.txt
telegram       ┘   (дедуп)          (TCP/url-test) (трафик+скорость)  v2ray.txt
                                                                    clash.yaml
                                                                    index.json
                                                                        │
                                                              publish_pub.py
                                                                    │
                                                        repo raw / gist raw
```

## Слои

**1. Источники и сбор** (`scan_any.py collect`, `scrape_web.py`,
`discover_channels.py`, `tg_scrape.py`). Каждый источник отдаёт текст, из него
регулярками вынимаются `vless://`, `vmess://`, `ss://`, `trojan://`, `hy2://`,
`hysteria2://`, `anytls://`, `tuic://`, а также base64-блобы (в них бывает
список ссылок целиком). Дальше — дедуп: сначала по строке, потом по
идентичности подключения.

**2. Проверка** (`scan_any.py latency|verify`, `sb_verify.py`, `pi_sb_verify.py`).
Один процесс sing-box поднимает N socks-inbound'ов, каждому соответствует свой
outbound. Проверка идёт `curl --socks5-hostname` через нужный порт. Так
исключается целый класс ошибок «ядро клиента не умеет этот транспорт».

**3. Отбор** (`publish_sub.py`). Дедуп по подключению **до** потолков, потолки по
протоколам, порог скорости, сортировка под профиль (дома hy2 первыми, на
мобильном vless первыми).

**4. Публикация** (`publish_pub.py`). Запись файлов атомарная (`.tmp` + rename),
затем публикация через GitHub API в репозиторий и/или гист, затем **чтение
назад** и сверка с локальным файлом. Расхождение = ошибка публикации.

**5. Страховка** (`sub_snapshot.py`). Перед публикацией — проверка целостности
текущего списка, после — самопроверка (количество нод и `mihomo -t` на
`clash.yaml`). Не прошло — откат из последнего снимка.

## Ключевые инварианты

- **Один источник правды для путей** — `scripts/paths.py` и `scripts/lib/env.sh`.
  Скрипты не содержат абсолютных путей и личных данных.
- **Проверка = условия клиента**: то же ядро, тот же транспорт, те же SNI/ALPN.
- **Никакой ноды в подписке без измерения трафика** — код 204 сам по себе ничего
  не доказывает (см. [filters.md](filters.md)).
- **Публикация идемпотентна**: повторный запуск даёт тот же результат и не
  ломает файлы, если новый список хуже прошлого.
- **Тихий отказ запрещён**: если публикация не удалась, уходит уведомление,
  а старый список остаётся рабочим.

## Почему не «просто проверить TCP»

Замер на мобильном операторе: из 101 кандидата TCP открывался у 87, а трафик
шёл у 13. Разрыв в 6,7 раза — это DPI, который пропускает рукопожатие и рвёт
данные. Поэтому TCP-фаза используется только как дешёвый предфильтр (экономит
секунды), но никогда как доказательство живости.
