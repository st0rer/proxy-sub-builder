# Домашний профиль (широкий канал, без DPI-потерь)

Задача: собрать максимально большой и быстрый список для клиента в сети, где
блокировки мягче (домашний проводной интернет, 300–500 Мбит/с).

## Цикл `refresh_subs.sh`

1. **Preflight.** Три эндпоинта; если ни один не отвечает — прогон отменяется
   целиком, подписка не трогается. Промежуточные файлы не перезаписываются
   пустотой.
2. **Свет погас посреди прошлого прогона?** Проверка целостности текущей
   подписки, при повреждении — восстановление из снимка **до** любых записей.
3. **Сбор.**
   - `scrape_web.py` — сайты-каталоги (vpnkeys.me: ключи перепроверяются каждую
     минуту, выход живыми 8/12 против 1/4 у GitHub-списков);
   - `discover_channels.py --search` — новые телеграм-каналы;
   - `tg_scrape.py 400` — ссылки из публичных превью;
   - `scan_any.py collect` — GitHub-списки и накопленный пул.
4. **Проверка.** `latency` (url-test через mihomo, отсев по TCP) → `verify 280`
   (реальный выход + скорость, Cloudflare 3 МБ) → `clean` (проверка, что нода
   ходит напрямую, а не через туннель роутера).
5. **Публикация.** `publish_sub.py` → снимок → самопроверка → `publish_pub.py`
   (репозиторий и гист).
6. **Уборка.** `gc_engine.py`: старые `clean_*.txt`, кэш гео-баз, мусор в
   `scratch/`.

## Потолки и порядок

```python
CAPS = {"hy2": 45, "vless": 60, "ss": 60, "trojan": 20, "vmess": 20,
        "ssr": 15, "tuic": 15, "anytls": 10, "hysteria": 10}
```

Порядок в файле = порядок перебора в клиенте. Для домашнего профиля hy2 идёт
первым: QUIC на проводных операторах живёт лучше, чем TCP с TLS-отпечатком.
Переопределяется `SUB_CAPS` и `SUB_ORDER`.

## Бюджет

Домашний трафик не лимитирован, поэтому `verify` берёт 280 нод, скорость
меряется у `SPEED_TOP=10` самых быстрых по задержке (по 500 КБ).

## Таймер

`systemd/subs-refresh.timer` — каждые 6 часов (`00/6:30`). Полный цикл идёт
8–20 минут, параллельно с мобильным он не запускается (общий `flock`).
