# Подводные камни

Собрано на своих ошибках. Каждый пункт стоил простоя или тихой потери нод.

## Проверка

- **`204` не доказывает трафик.** Заглушка (страница воркера, портал оператора)
  отвечает `200` на всё. Проверять размер тела на запросе `bytes=16384`.
- **Один URL даёт 27 % ложных отсевов.** Нужны три ступени и повтор.
- **Проверять надо тем же ядром, что у клиента.** Иначе «нода рабочая» на
  mihomo оказывается мёртвой в sing-box (anytls, XHTTP) — и наоборот.
- **TCP-порт открыт ≠ нода живая.** На мобильном операторе 87 из 101 открывались
  по TCP, трафик шёл у 13.
- **Флапающие ноды существуют.** Без второго прохода теряется ~28 % рабочих.
- **Ноль скорости бывает двух сортов** — «не мерили» и «мерили, не поехало».
  Нужен явный флаг `speed_measured`.

## Отбор и дедуп

- **Дедуп должен идти до потолков.** Иначе слоты уходят на переименованные
  копии одного сервера: подписка схлопывалась со 165 до 37 нод.
- **Дедуп по строке бесполезен** — одна и та же нода приходит с разными именами
  и эмодзи. Нужна идентичность подключения (протокол + сервер + порт + ключ +
  SNI + path + host).
- **Сортировать до дедупа.** Иначе остаётся первая копия, а не быстрая.
- **Свои «доверенные» ноды тоже надо проверять.** Список, который добавляется
  в подписку без проверки, рано или поздно наполнится мёртвыми ссылками —
  у нас так попали 4 ссылки на собственный воркер подписки.

## Публикация

- **Успешный HTTP ≠ файл обновился.** Читать назад и сверять.
- **GitHub отдаёт `401` на живой токен.** Ретраить; без ретрая клиент остаётся
  со старым списком, а ошибка выглядит как поломка токена.
- **Защита от деградации может держать мёртвый список.** Если старые ноды уже
  мертвы, сжатие надо разрешать явно.
- **Публикация — часть цикла.** Локальный файл без публикации = у клиента
  старый список.

## Сеть и блокировки

- **Цепочка (chain / detour / dialer-proxy) — не ускоритель.** Скорость равна
  минимуму из звеньев; она возвращает доступность адреса.
- **Hy2 через цепочку невозможна** — QUIC требует UDP от края до края.
- **Провайдер режет подсети целиком.** Бывает, что адрес недостижим на любом
  порту, а соседний работает: помогает перебор входных адресов той же панели.
- **Дневной троттлинг оператора** выглядит как «ноды сдохли»: ночью те же ноды
  дают 1,2 МБ/с, днём 0,1–0,3.

## Обвязка

- **`pkill -f "sing-box run"` убивает собственный шелл** — командная строка
  содержит ту же строку. Использовать `pgrep -x` и убивать по PID.
- **`set -u` + `${VAR#...}` на незаданной переменной** валит скрипт: объявлять
  переменные явно или использовать `${VAR:-}`.
- **Прогон по таймеру и ручной одновременно** портят общие файлы — нужен
  `flock`.
- **Счётчики должны знать все протоколы**: подсчёт без anytls/tuic дал
  «в файле 11, в индексе 13» и заблокировал снимок.

## Телеграм

- **Глубина не работает, работает ширина** (30 страниц = 0 живых, 400 каналов =
  поток живых).
- **`?q=` и `?before=` несовместимы.**
- **Агрегаторы хуже тематических каналов**: то, что там лежит, умерло месяц назад.
- **Не опрашивать каждые 30 минут** — конфиги не появляются так часто.

## Проверка (продолжение)

- **Одна битая ссылка валит весь конфиг.** `flow=xtls-rprx-vision-udp443`
  заставляет sing-box упасть на старте с `initialize outbound[45]: unsupported
  flow`, и тогда **все** ноды прогона выглядят мёртвыми. Такие ссылки надо
  выбрасывать до сборки конфига, а запуск проверять `socket.connect` на первый
  socks-порт, а не `sleep`.
- **Не проверять запуск по времени.** Если конфиг не поднялся, все проверки
  возвращают `000` за секунды — это выглядит как «ноды кончились».

## Отбор (продолжение)

- **Не собирать подписку из одной панели.** Шесть адресов одной панели дают
  красивую цифру «45 % живых», а потом панель умирает и уносит всю подписку.
  Потолок `SUB_MAX_PER_PANEL` (по умолчанию 3) держит разные сервера.

## Развёртывание на роутер (sb_refresh.sh / sbgen.py / cf-watchdog.sh)

- **`scp` на OpenWrt только с `-O`.** В dropbear нет `sftp-server`, современный `scp`
  по умолчанию идёт через SFTP и молча не копирует файл.
- **В одинарных кавычках переменные не раскрываются.** `ssh 'mv /tmp/x "$REMOTE_CFG"'`
  уводит `mv` в пустой путь: скрипт рапортует успех, роутер остаётся на старом конфиге.
  Путь подставлять локально: `ssh "mv /tmp/x '$REMOTE_CFG'"`.
- **Тот же капкан в `python3 -c '...'`.** Одинарные кавычки внутри кода обрывают строку —
  получаешь пустой результат и `except`, а не ошибку. Склеивать строки конкатенацией.
- **Деплой и замер должны жить на разных портах.** Сторож и refresh, сцепившиеся за один
  порт туннеля, по очереди убивают друг другу форвард. Провал `PUT` при этом записывается
  как «нода мертва», и в конфиг уезжает мусорный список.
- **`pgrep -f "<порт>:127.0.0.1"` убивает всё, где встречается эта строка** — включая чужие
  шеллы и параллельный замер. Держать PID туннеля в pid-файле и убивать адресно.
- **Фиксированный `sleep` после `ssh -f -N` не гарантирует готовность форварда.** Ждать
  ответа API циклом (до 10 с), иначе первый же запрос уходит в закрытый порт.
- **Один признак «нода жива» недостаточно.** Задержка, `loadCodeAssist` и ответ сервиса
  расходятся: узел с 220 мс отдавал `403` на всё (бан IP хостинговой подсети), при этом
  при замере был `401`. Гейт перепроверять в стороже, а не только в момент сборки.
- **Гейт можно мерить только с самого узла.** Без переключения селектора проба всегда
  показывает текущий выход — «все кандидаты плохие» при живом соседе.
- **`experimental.unified_delay` ломает деплой** на sing-box < 1.15: `check` падает с
  `unknown field`, конфиг не подменяется. Включать явным ENV.
